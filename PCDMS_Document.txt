# 系統設計規格書 (System Design Document)
**專案名稱:** PCDMS 系統升級 Phase 2 - 新增保養維修功能
**文件編號:** SAMY420_SD_001
**建立日期:** 2026-07-27
**版本:** V1.0

---

## 1. 專案概述 (Project Overview)
本專案為 PCDMS (Probe Card Data Management System) 第二階段升級，主要目標為實作第一階段 (Phase 1) 檢討後保留之核心功能，並全新開發「保養維修 (Maintenance & Repair)」與相關的「查詢與報表 (Query & Report)」模組。此模組將取代部分人工作業，確保 Probe Card 的維修履歷、保養排程、報廢與重大異常皆能數位化並與 MES 系統連動，同時提供 TA (技術人員) 績效計算之基礎資料。

*註：本文件依據 Phase 2 SA UI 畫面進行系統功能與資料庫邏輯設計。「PEIS 繪圖功能改善」部分待後續補充。*

---

## 2. 系統架構與介面 (System Architecture & Interfaces)
*   **前端介面:** Web 應用程式 (基於既有 PCDMS 框架，相容於企業標準瀏覽器)。
*   **後端邏輯:** 處理表單 CRUD、流程卡控 (Hold/Release)、排程演算法及報表數據彙整。
*   **外部介面 (Phase 1 & 2 關聯):**
    *   **MES 系統:** PCD 製造資料與驗證作業的資料傳遞 (Prod Relation, Accessory Data)。
    *   **HR/帳號系統:** 簽核作業與權限群組判定 (Access Log, 人員群組)。

---

## 3. 資料庫實體關聯設計 (Database ERD Concept)
為支援畫面的欄位，需新增/修改以下主要資料表 (Table)：

1.  `TB_PCD_MASTER`: Probe Card 主檔 (擴充目前狀態、保養次數、維修次數、總測試次數)。
2.  `TB_MAINTENANCE_ORDER`: 保養/維修單據主檔 (欄位：表單編號、申請類別(PM/REPAIR)、需求程度(普/急/特急)、PCD_ID、機台編號、狀態等)。
3.  `TB_REPAIR_DETAIL`: 維修明細檔 (紀錄「異常原因」勾選、「處理方式」勾選、維修前/後測量數值)。
4.  `TB_PM_DETAIL`: 保養明細檔 (紀錄各項檢驗項目如：焊接點品質、清潔針頭、針尖長度/直徑之 Pass/Fail 數值)。
5.  `TB_SCRAP_APPLY`: 報廢申請檔 (報廢原因、確認人員、Scrap Alert 次數等)。
6.  `TB_MAJOR_ISSUE`: 重大異常報告檔 (損壞情形、再發防止對策、附件路徑)。
7.  `TB_EQ_STATUS`: PRVX / MotherBoard 機台狀態檔 (機台名稱、目前狀態 IDLE/IN-USE)。
8.  `TB_PERFORMANCE_LOG`: 績效工時紀錄檔 (人員工時、總產出、各站點加權分數)。

## 4. 功能模組設計 (Functional Module Design)

### 4.1. 保養維修作業子系統

#### 4.1.1. 保養維修排程 (Maintenance/Repair Scheduling)
*   **功能描述:** 顯示待處理的 PM (保養) 與 REPAIR (維修) 清單，並依照「Priority (優先權)」排序。
*   **輸入與操作:**
    *   下拉選單選擇 `PRVX EQ Name`。
    *   點擊 [重新排程] 按鈕：後端觸發排程演算法，依據「需求程度(特急>急>普)」與「送件時間」重新計算 Priority。
*   **業務規則:** Mosaid/WAT/Vertical 類 Probe Card 不列入自動排程，需以手動點選進行。

#### 4.1.2. 保養/維修單建立與作業 (Order Creation & Operation)
*   **維修作業畫面:**
    *   **觸發點:** 點擊排程清單進入或手動建立維修單。
    *   **卡控邏輯:** 系統需自動帶入該 PCD 的 `AccuCnt` (累計次數) 與 `首次架機Fail` 標記。
    *   **資料儲存:** 
        *   異常區：記錄勾選的針位(內擠、外開...)、電性(DC/AC Fail)及 S4 測試溫度。
        *   處理方式區：記錄是否委外 (連動「委外作業」清單)、更換零件勾選。
        *   測量結果：記錄各 Pin/項目之 Min/Max 及 Pass/Fail 結果。
*   **保養作業畫面:**
    *   **檢驗項目清單:** 預設帶入 9~11 項標準檢查項目 (如：焊接點品質、針尖長度 20~55um)。
    *   **動作:** 使用者需輸入量測值，系統自動判定 Pass/Fail。

#### 4.1.3. 進度監控 (Progress Monitoring)
*   **功能描述:** 顯示所有處理中或已完成的維修保養案件。
*   **欄位計算:** 系統需自動記錄 `開始維修時間`，並依照表單類別與歷史平均 TAT 預估 `預計完成時間`。
*   *備註 (SA 反饋):* 簡報標示「還有在用嗎?」，開發前需向 User 確認是否保留此報表或以 Dashboard 取代。

#### 4.1.4. 報廢作業 (Scrap Operation)
*   **功能描述:** 針對無法修復之 PCD 進行報廢申請與簽核。
*   **輸入/檢核:** 選擇 Probe Card No 後，系統自動帶出 `Release日期`、`總測試次數`、`總維修/保養次數`。
*   **報廢原因:** 必須勾選至少一項 (嚴重撞毀、Tip < 5 mils 等)。
*   **關聯動作:** 報廢單送件後，PCD 狀態應變更為 "Scrapping (報廢簽核中)"，結案後轉為 "Scrap (已報廢)" 並從可用庫存剔除。

#### 4.1.5. 重大異常作業 (Major Abnormality)
*   **功能描述:** 針對嚴重損壞建立報告單。
*   **表單特徵:** 包含「損壞情形」詳細描述、「是否可維修」判定、「再發防止對策」純文字輸入。
*   **檔案上傳:** 支援「說明」與「防止對策」夾帶附件 (如照片、分析報告)。

#### 4.1.6. PRVX借用歸還 (Equipment Borrow/Return)
*   **功能描述:** 管理 PRVX 機台與 MotherBoard 的使用狀態。
*   **狀態機設計:** 預設狀態為 `IDLE`。使用者借出時變更為 `IN USE` 並紀錄借用人/時間，歸還時改回 `IDLE`。

## 5. 查詢與報表子系統設計 (Query & Report Design)

### 5.1. PCD 病歷表查詢 (PCD Medical Record)
*   **搜尋條件:** 時間區間、申請者、PCD ID、處理程序等。
*   **輸出欄位:** 彙整該 PCD 的所有生命週期紀錄 (包含維修、保養、報廢、首次架機 Fail)。
*   **資料匯出:** 支援匯出為 Excel (`.xlsx` 格式)。

### 5.2. 保養維修 TAT 查詢 (Turn Around Time)
*   **邏輯定義:**
    *   `T1分鐘`: 送件(申請) 到 處理完成(結案) 的總時間。
    *   `T2分鐘`: 開始作業 到 處理完成 的時間 (排除等待排程時間)。
    *   `T3分鐘`: 實際作業工時 (扣除休息、Hold 的時間)。
*   **Hold Reason:** 若工單曾經 Hold，需提供超連結檢視 Hold Code 與原因說明。

### 5.3. 績效 Report (Performance Report)
*   **輸入條件:** 查詢年月 (Year/Month)。
*   **產出報表 1 (生產效力計算):**
    *   收集 TA 的 `總工時` = (上班日數 * 每日工時) + 加班 - 請假。
    *   產出分數計算 = `PCDMS產出加權` + `解銲` + `機台產出`。
    *   最終績分 (Rank) 計算。
*   **產出報表 2 (維修組績效總表):**
    *   按員工工號，列出各項作業 (Versa+Mosaid, PB6800, V-PCD PM, Epoxy清針等) 的處理件數/時數。
    *   **系統核心公式:** `合計總分 = Σ (各項作業項目分數 * 計分權重)`。計分權重需建立後台設定介面 (Parameter Table) 供主管動態調整，不可寫死於程式碼中。
*   **產出報表 3 (月度趨勢):** 以 1~12 月橫向展示各員工每月的平均效力指標 (Avg)。

## 6. 例外處理與資安設計 (Exception & Security)

1.  **併發控制 (Concurrency):**
    *   同一張 Probe Card 同時間只能存在一張未結案的維修/保養單。系統在「建立維修單」時需進行 Lock 與檢查，若已有進行中工單則阻擋建立並跳出提示。
2.  **資料完整性 (Data Integrity):**
    *   表單中帶有紅星號 `*` (如報廢作業的 Location, 總測試次數) 皆為必填欄位。前端需做 JS 驗證，後端 API 亦需再次檢核。
3.  **防呆機制:**
    *   若輸入測量數值超出規格上限 (Max) 或下限 (Min)，系統自動將 [檢查結果] Radio Button 標示為 Fail，並高亮警告。
4.  **權限控管:**
    *   (繼承 Phase 1 IT 設定模組) 只有主管 (H/W Leader) 可簽核重大異常與報廢單。一般 TA 僅能執行與檢視個人工作。
